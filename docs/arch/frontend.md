# Frontend and UI

_GrandForge reference. Load this file only when working in this area; see [CLAUDE.md](../../CLAUDE.md) for the routing table._

Single-page app (`frontend/src/App.tsx`): `/` and `/game/:id` both render `AnalyzerPage`; static content routes `/privacy`, `/learn/chess-accuracy`, `/learn/move-classifications` render prose pages via the shared `StaticPage` shell (`frontend/src/pages/StaticPage.tsx` — Header/Footer + `.static-prose`, styles at end of `frontend/src/styles/global.css`); everything else is `NotFoundPage`. The content pages are SEO entry points (linked from `Footer`, listed in `frontend/public/sitemap.xml`) and rely on `vercel.json`'s catch-all rewrite `/((?!api/).*) → /index.html` for direct-load/refresh — no per-route config. When adding a content page: create it, register the route, link it in `Footer`, add it to `sitemap.xml`. The board is `react-chessboard`, move legality/SAN/FEN via `chess.js`. `useAutoAnalysis` debounces (150 ms) live analysis on every FEN change and stops on terminal positions. Components are grouped by domain under `frontend/src/components/` (board, engine, evaluation, review, import, navigation, layout, ui). Path alias `@/*` → `src/*`.

**Board overlays**: `ChessBoardWrapper` wraps `<Chessboard/>` in a `.gf-board` relative container and renders two overlay layers on top of it:

- `BoardMarkerOverlay` — DOM-based markers for click-to-move: selection highlight (`.gf-sel`), legal-move dots (`.gf-dot`), and capture rings (`.gf-cap`). These replace the old inline `customSquareStyles` approach so they can carry gradients and CSS animation. `captureTargets` (a `Set<Square>`) tracks which legal moves are captures/en-passant. Styles in `frontend/src/styles/board.css`.
- `BoardArrowOverlay` — custom SVG arrows (single filled polygon per arrow, chess.com/lichess style). react-chessboard's built-in arrows (`customArrows=[]`, `areArrowsAllowed=false`) are suppressed because its thin-line + detached-head rendering can't be reshaped. Arrow geometry (shaft width, head proportions, gaps) is tuned in percentage-space constants. A stable `NO_ARROWS` empty-array ref avoids re-running the library's arrow memo.
- Engine arrow colors use a rank hierarchy: best move = vibrant emerald `#2fc85a`, alternatives = deeper green `#1f9d4d` with progressively lower alpha per rank. `engineArrowColor(rank, opacity)` in `useArrowLayers.ts` computes per-arrow color.

**Explore tab** (`frontend/src/components/explorer/ExplorePanel.tsx` + `frontend/src/hooks/useExplorer.ts` + `frontend/src/utils/explorerFormat.ts`): the opening-explorer panel — ECO name + our own theory prose (`opening.description`, mostly unwritten yet), position W/D/L bar, a clickable move table, and representative games. Reads **our** aggregate via `explorer.lookup` in `apiClient.ts`; no third-party service is contacted and nothing in the copy names or links to one. Two cost controls, both load-bearing on the free tier: `SidePanel` renders only `panel[effectiveTab]`, so an unselected panel never mounts and the hook never runs (`useExplorer(active)`'s flag doubles the gate for a future always-mounted layout), and the response is cached hard (route sends `max-age=86400`, react-query `staleTime: Infinity`, `retry: false`) because the aggregate is static between ingests. `useExplorer` keys on `getPathToNode(moveTree, currentNodeId)` — the **current line**, not the mainline — so exploring inside a variation resolves that variation's opening (`useOpeningDetect` still reads the mainline). Beyond `MAX_EXPLORE_PLIES = 24` it stops asking, since past the ingest's `--max-plies` every answer can only be `null`. The arithmetic lives in `explorerFormat.ts` so it can be unit-tested: `wdlPercents` rounds then hands the drift to the largest bucket so the bar always sums to exactly 100, `formatShare` floors a nonzero share at `<1%` rather than `0%`, `scorePercent` counts a draw as a half point (not an average of win rates), and `sortTopGames` ranks on the **weaker** player — same rule as the ingest, so a 2800-vs-1400 rout can't represent a position. Side-panel tabs are the `SidePanelTabId` union exported from `uiStore.ts` (state field, setter and persisted shape all reference it — adding a tab is one edit); `activeTab` is persisted, and widening the union needs no migration.

**Eval graph** (`frontend/src/components/review/EvalGraph.tsx`): the review's evaluation area chart, shown above both the summary card and the playback panel in `ReviewTab`. White-relative eval per ply (mover-relative `evalAfter` flipped on odd plies; mate folded to ±1000cp), tanh-squashed so ±350cp ≈ 75% of the half-band. The white fill sits **below** the curve — white better → curve up → bigger white area (the first cut was inverted; don't flip it back). Click / arrow keys jump to a ply via `getNodeIdAtPly` + `reviewedNodeIds`; the current-move cursor is the index of `currentNodeId` in `reviewedNodeIds`. Key-moment dots reuse the classification palette from `ReviewSummaryCard`. Styles at the end of `frontend/src/styles/review.css`.

**Blunder-puzzle trainer** (`frontend/src/components/review/BlunderPuzzleTrainer.tsx` + `frontend/src/utils/blunderPuzzles.ts`): "Fix Your Blunders" — a `secondary` button in `ReviewTab`'s complete-state summary that swaps the view (`showPuzzles` local state) for a puzzle trainer. `buildBlunderPuzzles(result, tree)` extracts every `mistake`/`blunder`/`miss` move into a puzzle: the FEN **before** the played move is the reviewed node at the *same* plyIndex (`getNodeIdAtPly(tree, plyIndex, reviewedNodeIds)` — a node's fen is the position AFTER its move, so node[plyIndex] is the position move plyIndex was played from), and the solution is that move's `bestMoveUci`. Puzzles sort worst-first (highest CPL). The trainer is fully self-contained: its own `chess.js` per drop for legality, no engine call, no store mutation; a wrong move snaps back (`onPieceDrop` returns false), correct == `bestMoveUci`. Extractor is unit-tested (`frontend/src/utils/blunderPuzzles.test.ts`); board theme via `useUIStore.boardTheme` + `BOARD_THEMES`. Styles (`.bpt-*`) at the end of `frontend/src/styles/review.css`.
